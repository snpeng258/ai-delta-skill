# ai-delta-skill

生成变便宜了，验证没有。所以稀缺资源只有一个：**我的验证带宽**。

这个库是一份 skill：agent 只读根目录 [SKILL.md](SKILL.md)，再按需读词汇和拓扑。规矩：**我只管说话，记录是副产品。** 不填表，不整理，不设"整理时间"。

## 给 agent 的三份，给自己的一份

| 文件 | 谁写 | 谁读 | 一条长什么样 |
|---|---|---|---|
| `vocab.md` | skill | skill | 外行说法 · `ob:` 标记 · 搞混过 · 拓扑检索；叠加时加一行 |
| `topology.md` | skill | skill | 层名 — 判据 |
| `cases.md` | skill | **我**（整理时全文读） | 日期｜标签｜现象｜缺什么｜`ob:<source>/<session_id>` |
| 说法笔记本（本机：`~/Desktop/ai-delta-phrasing.md`） | **我** | **我** | 一句我自己用的话 + 来自哪几条 case |

分界线：**一条记录如果需要看别的记录才能写，就不该自动写。** 前三份都是当场就知道的事实。说法要跨多条案例比较——那是判断，是我唯一产生价值的地方，也只给我自己看。

说法笔记本**不在 skill 文件夹里**。本机放桌面，方便常看。发给别人的 skill 里不要带这份文件——每人自己放在会打开的地方。全文加载发生在我整理 `cases.md` → 说法的时候，不是每次对话。

`why.md` 是这些为什么长这样。读一次就够，不用维护，agent 也不要默认加载。

## 触发：我说这句话，skill 就该动笔

| 我随口说的 | skill 做什么 |
|---|---|
| "什么是 X" "X 是什么意思" | `vocab.md` 新建一节或叠加一行 |
| "这项目分几层" "这结构怎么回事" | `topology.md` 建一节或补一行 |
| "这个例子很好" "这次很对" | `cases.md` 加一行 `(+)` |
| "又碰到那个问题了" "它又修错层了" | `cases.md` 加一行 `(a/b/c/d)` |
| 同一类问题第五次进 `cases.md` | 随口提醒我可以去整理案例，不要去找说法笔记本 |

写的时候不许反问我要补什么字段。信息不够就少写半行，宁可漏，不要打断我。

## 两条规矩

**一、写入只由说话触发，当场完成，一条不超过一行。**
做事和学习已经解耦，偷懒会被立刻奖励（更快交付），惩罚延迟几个月才到。所以任何依赖"我要更用心"或"等有空整理"的方案都会死。

**二、说不出差别就不记。**
判据：这件事换个人加同一个模型，结果会差多少？差不多就别记——那是中位解，收藏它只是攒景观。

## 第四层：卡片怎么用

**词汇和拓扑：循环叠加。** 调用时先只读所有 `## ` 标题。标题自带一句话摘要，本身就是索引。只对看起来相关的小节展开全文。讲解时最多提两条关联候选；我确认之后叠一层。

**案例：攒着给我。** skill 只追加一行，不读、不总结、不提炼。我整理成说法时，自己**全文加载 `cases.md`**，写到桌面上的笔记本。

**说法不进上下文。** 它是笔记本，不是约束，也不在 skill 包里。某一行真的要让机器执行，我另搭脚手架或独立 skill——那时候进上下文的是新文件，不是这份笔记。

### 这一层还没定的

- 一条说法降级成机器约束之后，底部那行要不要留原始出处
- 降级产物放哪（项目里的 lint/hook，还是一份新的 skill）

## 唯一的进度条

说法笔记本里的一行，挪到「已经不用说了」，并且另有一份机器约束真正接住它。

从"我每次都得说"变成"机器帮我挡"。这个挪动次数是唯一不依赖自我感觉的进步指标。
